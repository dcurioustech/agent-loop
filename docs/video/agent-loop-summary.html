agent-loop
A checkpoint-gated developer / reviewer loop
for coding-agent CLIs.
The idea

One agent builds. Another agent reviews.

🛠️

Developer

Writes the code for the current checkpoint, then marks it built

→code + commit
←specific notes
🔍

Reviewer

Runs build / test / lint against exit criteria. Approves — or sends it back.

Unattended, auditable, and committed to git one checkpoint at a time.

The state file

Work is a list of checkpoints

// plan_checkpoints.json
{
  "branch": "feature/login",
  "project": {
    "build_cmd": "npm run build",
    "test_cmd":  "npm test",
    "lint_cmd":  "npm run lint"
  },
  "checkpoints": [{
    "id": "phase0",
    "status": "pending",
    "exit_criteria": ["..."],
    "attempts": 0, "review_notes": ""
  }, …]
}
pending
not started yet
built
developer done, awaiting review
approved
reviewer signed off — skipped on resume
Project-agnostic: each repo declares its own build / test / lint commands.

Guardrails

Built to run unattended — safely

🚫 Never on main

Refuses to run (or init) on main / master.

🔐 Explicit auto-mode gates

Won't start unless the provider's gate is set, e.g. ALLOW_AUTO_MODE_CLAUDE=1 — so runs never stall on a permission prompt.

🧹 Clean-worktree preflight

Uncommitted source changes block the run (log files excepted).

✋ Bounded retries

Halts for human review after N failed review attempts instead of looping forever.

Audit trail

Every run leaves a committed log

AGENT_TRACE agent start · prompt · finish
REVIEW_COMMENT reviewer notes + status
APPROVAL_COMMENT checkpoint approved / skipped
COMMIT_STATEMENT commit hash (or none needed)
RUN_OUTCOME completed · halted · failed
--audit-levelRaw agent output in git
offsuppressed (default)
redactedbest-effort secret scrub
fulllogged as-is

Logs land in logs/loop_<timestamp>.log and are committed on every exit path.

agent-loop init

From a feature idea to a validated plan

1 · Describe

"Add a login page with email/password auth and a logout button"
or --feature-file docs/feature.md
→

2 · Plan

A provider CLI breaks it into ordered, independently reviewable checkpoints.
→

3 · Validate

Written only if it parses and passes the schema. Never overwrites without --force.
$ agent-loop init "Add a login page" && agent-loop validate && agent-loop status
Get started

Four commands

$ pipx install git+https://github.com/dcurioustech/agent-loop.git
$ agent-loop init "Add CSV export to the reports page"
$ export ALLOW_AUTO_MODE_CLAUDE=1 ALLOW_AUTO_MODE_CODEX=1
$ agent-loop run
### All checkpoints approved on branch feature/csv-export.
